## Follow-up: logical framebuffer feedback implemented

The previously failing diagnostic now passes and is registered as the normal
`path3_feedback_tests` CTest. Gs can bind to Gif's existing4MB logical color
storage for FRAME PSMCT32/24 targets, using FRAME base/width and write mask.
Texture reads and accepted raster writes now share that storage. Blending reads
the selected target destination. PSMCT24 writes preserve the stored high byte;
PSMCT24 texture reads discard it and derive alpha from TEXA.TA0/AEM.
The PSMCT24 expansion and high-byte preservation were checked against:
https://raw.githubusercontent.com/PCSX2/pcsx2/v2.8.2/pcsx2/GS/GSLocalMemory.h

Scope is deliberately limited: linear memory, not native GS swizzling. One
accepted quarter-scale raster sample replicates into a4x4 logical native tile;
reads take the tile-origin sample. Access wraps at4MB; x beyond the declared
buffer width is excluded in this subset. Depth remains the existing host buffer,
not per-ZBUF guest storage. Unsupported FRAME formats/zero width use the old
standalone path. PSMCT24 IMAGE upload,16-bit TEXA corrections, scanout selection,
linear filtering, general overlap hazards and native-resolution edge coverage
remain unimplemented. The displayed image is a preview of the most recently
bound draw target, NOT the privileged GS display circuit.
