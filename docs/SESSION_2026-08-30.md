# AstraRecomp session handoff — 2026-08-30

## Milestone reached

AstraRT now validates generated package metadata before executing native code.
The package contract includes:

- AstraRT ABI version;
- guest address bounds;
- a lowercase SHA-256 source fingerprint;
- a non-empty, strictly sorted function table;
- aligned, non-empty, non-overlapping entry ranges;
- non-null translated function pointers.

Malformed packages return an `Interpreter` exit without invoking translated code.
Bounded dispatch validates once before entering its function loop, so validation
does not add an O(entry-count) scan to every native call or return.

The Phase-0 caller range was split at its resumable `0x3008` entry. This makes
the generated metadata non-overlapping while preserving exact-entry lookup and
the existing JAL/delay-slot/`jr $ra` behavior.

## Automatic backend milestone

The first deterministic ELF-to-AstraRT generator is now integrated into CMake.
It emits the validated package, aggregate source fingerprint, exact basic-block
table, and compact native functions during both host and Vita builds. The manual
Phase-0 translated bodies were removed from `src/core/aot.cpp`.

Supported slice:

- `ADDIU`, `ADDU`, `LW`, and `SW`;
- `J`, `JAL`, `JR`, `BEQ`, and `BNE` with data/NOP delay slots;
- direct, indirect, terminal, and interpreter exits;

## BIOS/IOP bring-up milestone

The retail reset ROM now passes its former EE address-error exception and reaches
the installed kernel. The fault was traced to missing R3000A cache-isolation
semantics: while CP0 Status bit 16 was set, the IOP reset ROM issued ordinary RAM
stores to invalidate cache lines. AstraRecomp committed those stores into mirrored
IOP RAM, erasing one word from every 16-byte line of the low-memory bootstrap and
eventually executing a saved return address as an instruction.

IOP RAM stores are now suppressed while cache isolation is active, while hardware
and scratchpad accesses remain live. A regression test covers the behavior. A
22,000,000-step trace completed the BIOS's 32 MiB EE memory clear, entered RAM code
on both processors, and emitted:

## Guest-generated SIF boot and kernel idle

The temporary SIF boot-event state machine has been removed. A trace with that
bridge disabled proved that interpreted IOP code produces both required events:

```text
IOP PC 00016C6C -> SMFLAG 00010000 (SIFINIT acknowledgement)
IOP PC 00017738 -> SMFLAG 00040000 (EESYNC BOOTEND)
```

The EE still reaches `Initialize Done` in 22,000,000 steps with no fabricated
flag transitions. SBUS tracing remains in `ps2bios_trace` to preserve evidence of
the guest-generated handshake.

The next post-initialization loop exposed incorrect R5900 `DI`/`EI` semantics.
Those instructions control Status.EIE at bit 16, subject to EDI/EXL/ERL/kernel
permission, rather than changing the generic IE bit 0. Correcting this advances
the BIOS from the `DI` retry loop into its kernel idle scheduler at `0x000842D0`.
Regression coverage verifies EIE changes, IE preservation, and user-mode denial.

GIF/GS tracing currently shows initialization writes only. No GIF DMA start has
occurred. The idle kernel polls the zero word at `0x000937C0`; its INTC mask is
`0x1002` (SBUS and the kernel-reserved Timer 3), identifying SIF DMA/interrupt
wakeup as the next boundary before packet delivery.

## Cycle-scheduled SIF1 command delivery

The coworker strategy review reinforced two constraints for the next boundary:
keep the interpreter as the deterministic oracle, and schedule device completion
against the EE master cycle count instead of completing DMA synchronously inside
an MMIO write.

The BIOS trace showed the EE SIF1 source channel armed with a two-tag chain at
`TADR=0x21380`: a three-QWC `REF` followed by a two-QWC `REFE`. The IOP had armed
its SIF1 receive channel at `0x1F801538`. The new bounded SIF1 path scans that
observed chain, schedules the deadline from its total QWC count, copies each
tagged packet from EE RAM into IOP RAM only when the deadline expires, and then
updates both DMA engines and interrupt controllers. Unsupported tag modes remain
an explicit boundary rather than being guessed.

Host regression coverage verifies pre-deadline invisibility, REF/REFE payload
delivery, channel completion, EE DMAC IP3 entry, IOP INTC entry, guest interrupt
acknowledgement, and the IOP-to-EE SBUS interrupt request. In the 30-million-step
retail BIOS trace, the IOP consumes the delivered command and arms SIF0 channel 9
with `CHCR=0x01000701` and `TADR=0x179BC`. This replaces the kernel-idle boundary
with a concrete IOP-to-EE reply boundary.

## SIF0 reply and EE interrupt entry

The next trace stopped when the IOP armed SIF0 at `TADR=0x179BC`. That tag sends
six words from IOP RAM `0x19870`, followed by an EE CNT/IRQ tag requesting two
QWC at `0x935C0`; the final two words are bus padding. A bounded SIF0 event now
schedules from the IOP word count, preserves the tag pointer's legal four-byte
alignment, delivers and pads the EE packet at the deadline, advances both DMA
engines, and raises their completion state.

The retail BIOS now leaves the kernel idle loop, enters the EE DMAC IP3 handler,
and reaches its packed accumulator-save sequence. The interpreter gained the
exact MMI operations encountered there: `PMFHI`, `PMFLO`, `PMTHI`, `PMTLO`,
`PCPYLD`, and `PCPYUD`, with full 128-bit and alias-safe regression coverage.

## Complete EE DMAC context-save semantics

The SIF0 wakeup first exposed `MFSA` at `0x80013F9C`, then `PEXTLW` at
`0x80013FAC`. The interpreter now keeps the R5900 shift-amount register as
architectural state, implements its `MFSA`/`MTSA` round trip, and implements the
four-word `PEXTLW` interleave with source snapshots so the BIOS's `rd == rt`
form is alias-safe.

With these semantics the retail BIOS no longer stops inside the EE DMAC context
save. It remains running at 30,000,000 steps, over 9.5 million instructions past
the former boundary. The current kernel path polls EE INTC SBUS bit 1 while the
IOP's real DMA interrupt dispatcher and callback execute. No synthetic SBUS event
has been added; the next task is to trace the expected guest ICFG bit-1 request
or identify the exact SIF command state that precedes it.

## IOP Timer 5 deadline and interrupt

Tracing past the SIF0 callback showed the IOP deliberately idle with INTC mask
bit 16 enabled. Its 32-bit Timer 5 had mode `0x70` and a one-second-scale target,
but its count remained zero because the device was not modeled. Timer 5 now
derives IOP cycles from the scheduler's EE master timeline, preserves fractional
8:1 phase and prescaler phase, detects exact target and overflow crossings, and
raises the observed IOP interrupt line.

The mode register models the separate internal interrupt-enable, target, and
overflow flags. Reads return the pending event before acknowledging it and
rearming the interrupt latch. Targets written at or behind the current count are
correctly deferred until the next wrap instead of firing immediately.

Host regression coverage verifies the exact pre-deadline/deadline boundary,
target acknowledgement, overflow wrap, and INTC delivery. In a 30-million-step
retail BIOS trace both processors remain running with no invalid instruction;
Timer 5 advances to `0x001DF03B`, its target event is serviced, and the EE moves
forward in the kernel wait path without a fabricated SBUS wakeup.
