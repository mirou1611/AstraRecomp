# Session 2026-09-24: VU1/VIF execution-path optimization

The first captured BIOS VIF1 packet is the local performance and correctness
workload. It still executes 998 VU pairs in 1308 modeled cycles, ending at
micro-PC 0x0308; VU registers, all 16 KiB of VU data RAM, and PATH1 counters
hash to `B914A64CD3201B71` before and after the changes. The delivered GIF
packet bytes and first rejected-tag snapshot hash to `19964F619C2D7AC8`
on the optimized run. This is not a new intro frame or a fix for its
suppressed geometry.

## Changes

- Replace the 31-register-by-four-lane readiness scan with the up-to-two
  vector sources actually read by each instruction. Preserve per-lane hazards.
- Snapshot only the lower instruction's VF sources before upper execution,
  retaining the same-pair read-before-write behavior and VF0 source value.
- Add aligned VU1-local micro/data word and data-qword accessors. VU1 no longer
  routes every local fetch/load/store/GIF transfer through the EE bus decoder
  and TLB. VIF1 MPG/UNPACK uploads use the same local banks while preserving
  its causal/provenance records.
- Add `ps2vu_benchmark` and bank-edge/coherence unit checks. The benchmark
  rejects nondeterministic VU state or delivered GIF packets across repetitions.

## Measured result

Release `-O3` WSL host, 2000 repetitions of the local 3936-byte capture:

| Stage | Timed VIF submit / VU pair-equivalent |
| --- | ---: |
| Before optimization | 1660.55 ns |
| Compact readiness | 1547.43 ns |
| VU-local reads | 595.72 ns |
| VU-local stores and GIF qwords | 420.19 ns |

With VIF1 MPG/UNPACK local-bank writes, three 5000-repetition samples were
71.08, 70.11, and 69.25 ns per pair-equivalent, roughly 23x faster than the
initial local measurement. The timed interval is the entire `Vif1::submit`,
including upload, parsing, and VU execution. Reset and checksum happen outside
that interval. This is a host throughput number, **not** VU-only speed or Vita
frame rate. The BIOS-derived capture stays local and is not committed.

A call-count profile of 5000 repetitions fell from about 4.77 million generic
`Memory::write32` calls in VIF submission to none in that path. Its total-time
percentages are dominated by the benchmark's untimed full-RAM checksums, so
they should not be mistaken for a VU-only cycle profile. Upper/lower arithmetic
dispatch is now the next interpreter cost worth measuring separately; guessed
math shortcuts would risk the unresolved clipping behavior.

To reproduce with an independently obtained VIF packet:

```sh
cmake --build build-release --target ps2vu_benchmark
./build-release/ps2vu_benchmark path/to/capture.bin 2000
```

Release CTest 14/14 and UBSan CTest 14/14 pass. A Vita VPK cross-build also
passes; no physical Vita runtime measurement is claimed. The benchmark's
checksum protects final state and GIF counters, while the existing per-lane,
same-pair, VIF provenance, XGKICK, and bank-edge tests guard intermediate
contracts. Remaining work: compare this exact VU input and flag decisions
against a trusted reference before changing clipping behavior. An offline VU
microprogram compiler is a later performance step; it must use this path as a
correctness fallback, not assume the present 998-pair run is visually correct.
