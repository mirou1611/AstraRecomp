## Verified fixes

ADD/SUB/MUL, ADD/SUB broadcasts and MULq previously skipped the entire MAC update
when their destination was the immutable VF0 register. The destination must stay
unchanged, while active lanes update flags and inactive lanes clear their flag
bits. The fix separates result disposal from flag computation. MAX continues to
preserve MAC, and the existing four-cycle visibility model is unchanged.

The dedicated `vu1_flag_tests` target checks 962 finite-value properties across
16 supported VF arithmetic opcodes, four lane masks, VF0/ordinary destinations,
accumulator controls and MAX. Two SUB-to-VF0 / FMAND / IBNE microprograms verify
both branch outcomes, pre-visibility reads, delay slots and normal termination.
The initial broader test reproduced the bug before the fix; unsupported float
edge-case assumptions were excluded from the retained suite. Expected constants
are independently specified, not copied from Astra output. This fixes a real
branch-visible error, but does not change the captured BIOS packet's output.

DIV also used native IEEE arithmetic for zero/denormal divisors, allowing NaN/Inf
in Q. Zero and denormal inputs now use the VU signed-zero boundary behavior;
division by a zero/denormal divisor saturates Q to signed `7F7FFFFF`, including
0/0. Normal-divisor zero/denormal numerators preserve XOR-signed zero. Pending Q,
the seven-cycle ready horizon and WAITQ remain unchanged. `vu1_div_tests` checks
180 properties including a subsequent MULq consumer. Its initial zero-divisor
subset failed 34 checks before this fix. I/D status flags are not yet modeled;
normal finite division precision and extended-exponent behavior remain open.

Architectural behavior was checked against the pinned
[PCSX2 v2.8.2 VU instruction implementation](https://github.com/PCSX2/pcsx2/blob/v2.8.2/pcsx2/VUops.cpp).
All implementation and fixtures were written independently; no upstream code
or copyrighted input was imported into the repository.

## Second resumed milestone: exact controlled functional memory agreement

The previous resumed checkpoint was pushed as `868555b`. This section records
the subsequent investigation and supersedes its current arithmetic/test status.

The reference's color mismatch was an input-version problem. First-call LQI at
microPC `0048` reads ambient light from VU byte address `00B0`, intended to contain
`3ECCCCCD,3ECCCCCD,3ECCCCCD,3F800000`. A following UNPACK overwrites the same
address with four `43000000` color inputs. In the unsynchronized reference,
VF12 becomes 128 before the first call finishes. The matrix helper similarly
can consume new normal data at `0070` instead of its intended translation input;
the interpreter's projection translation incorporates VF3, changing VF24.w from
`40200000` (2.5) to `40233333` (2.55). That explains the two modes' earlier Q
disagreement without inventing a new arithmetic rounding rule.

Inserting FLUSHE after the first MSCAL removes both aliases: microVU and the
interpreter now agree exactly, and colors become Astra's `33,33,33,80`. Owned
post-call diagnostic stores also compare VF/ACC/Q and all VI registers: all 32
diagnostic qwords match Astra after both the first call and synchronized first
MSCNT. VI5 is zero after the first call and `E` after its first continuation.
These experiments preserve captured microinstructions and input words, but
deliberately change upload/execution ordering. They are not original BIOS timing
or physical PS2 evidence.
