## Dual-core SPU2 DMA checkpoint

The preserved SPU2 experiment initially regressed the retail BIOS from the
verified 434 SIF0 activity transitions to 20. A stop at the first stalled poll
showed that the BIOS initializes and starts both SPU2 DMA paths together:

- DMA4/core 0: MADR `0x0004FA00`, BCR `0x00300010`, CHCR `0x01000201`;
- DMA7/core 1: MADR `0x0004FA00`, BCR `0x00300010`, CHCR `0x01000201`.

The core-0 server then polls SPU2 status `0x1F9001B0` and DMA4 MADR
`0x1F8010C0`. Persistent SPU2 register readback exposed this real wait, but the
experiment modeled only DMA7, so DMA4 never advanced and the IOP remained in
the poll loop.

The timed SPU2 transfer model now covers DMA4 and DMA7. Each core keeps
independent source, TSA, byte-count, and deadline state; completion copies the
IOP payload into sound RAM, advances MADR and TSA, clears BCR/CHCR start, sets
the appropriate DICR status bit (DMA4 bit 28 or DMA7/DICR2 bit 24), and raises
the shared IOP DMA interrupt line. Focused tests cover both channels.

The 200-million-step retail replay recovers exactly 434 SIF0 activity
transitions with both processors still running. Extending the replay to 250
million steps remains instruction-valid but does not increase the SIF0 count or
start post-initialization VIF/GIF DMA. The final sampled state is EE PC
`0x00081FDC`, IOP PC `0x000974F8`, with 34 stores to the traced RPC wait-state
range. This is a correctness checkpoint, not a visible-graphics claim.

## Optimization-plan alignment

The coworker-provided unconventional optimization plan was reviewed in full.
Its central recommendation is compatible with the current architecture: retain
the exact interpreter as oracle/fallback, but make the PC side profile-guided
and remove emulator-shaped work through guarded traces, width-aware AstraIR,
event horizons, and certified polling-loop collapse.

The next major optimization milestone should therefore be the plan's Phase A:
emit a compact, versioned, machine-readable execution census from a 200-million
step BIOS run without changing architectural behavior. Initial fields should
cover EE/IOP block and edge counts, indirect targets, event spacing, MMIO poll
sites, and DMA sizes. The observed SPU2 DMA4 polling loop is a useful report-only
`WAIT_DMA_COMPLETE` candidate; acceleration must wait for explicit timing,
guard, and fallback contracts. After the census is stable, introduce a minimal
AstraIR for the already-supported AOT subset rather than expanding a monolithic
emitter.
