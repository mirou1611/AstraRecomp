## Delay-slot interrupt and CDVD region milestone

The undefined syscall occurred when an asynchronous interrupt arrived after a
branch had been decoded but before its delay slot retired. Interrupt entry
discarded the pending target, so ERET resumed at the delay slot and fell through
to the idle trampoline's normally unreachable syscall instruction. EE interrupts
are now deferred until the branch/delay-slot pair retires. A focused regression
test raises Timer 3 in that exact window and verifies interrupt EPC at the branch
target. The retail BIOS passes the old 86,615,524-step panic boundary and remains
healthy at 100 million instructions.

That correction exposed CDVD Mechacon command `0x03`/parameter `0x00`, followed
by region command `0x36`. The former now returns its four-byte version and the
latter returns the complete 15-byte European region block. Command `0x36` falls
from 24 one-byte-error retries to one completed transaction. Both responses have
register-level regression coverage. The next visible-boot boundary remains the
first post-initialization GIF submission; no physical-Vita claim is made yet.

## SIF1 NEXT-chain and OSDSYS loading milestone

At the previous idle snapshot the EE had entered `WaitSema` with SIF1 CHCR still
armed. The matching IOP receive channel was also armed, disproving the initial
theory that a delayed IOP alarm needed to re-enable transport. The EE source
chain instead contained a zero-QWC `NEXT` tag that jumps from `0x00021570` to a
separately allocated `REFE` tag at `0x00021380`. The SIF1 engine accepted only
`REF` and `REFE`, so it rejected that legal chain shape before scheduling DMA.

SIF1 now follows the observed zero-length `NEXT` jump in both its validation and
execution passes. A focused regression chain transfers packets on each side of
the jump and verifies final TADR at the jumped `REFE` tag. In the 105-million-step
retail replay, EE execution advances from the kernel idle loop to `0x00200DF0`,
SIF0 activity rises from 50 to 218 transitions, and the IOP streams consecutive
16 KiB blocks through EE address `0x007B4000`. Both processors remain valid. No
post-initialization VIF/GIF DMA has started yet, so this checkpoint claims real
OSDSYS loading progress rather than visible intro pixels.

The extended 200-million-step replay reaches 434 SIF0 activity transitions and
shows an EE-side request for `rom0:FONTM`, the ROM font resource needed by the
OSD. It completes additional resource transfers without a CPU panic or memory
fault. Dedicated trace counters confirm zero post-initialization VIF0, VIF1, and
GIF DMA starts through this boundary. This proves that guest graphics are not
being silently discarded by the current placeholder GS path: OSDSYS has not yet
submitted its first graphics DMA workload. The next boot blocker is therefore
still before the VIF/GIF-to-GS packet and rendering stages.
