# Session 2026-08-31

## Retail BIOS interrupt and transport milestone

The previous retail trace reached a valid SIF0 interrupt but entered the general
exception vector. R5900 level-one interrupts now use their dedicated normal and
bootstrap vectors at `0x80000200` and `0xBFC00400`. The first instruction exposed
there was PLZCW, which now implements the two low-word leading-sign counts while
preserving the destination register's upper 64 bits.

The corrected handler returned to relocated BIOS code, where an EE access to the
physical CDVD aperture at `0x1F402000` exposed the next mapping boundary. EE byte
accesses now share the existing IOP CDVD device state. This removed the BIOS fatal
state `0x24`; the guest prints the DECI2 Manager banner and its CPUID, BoardID,
ROMGEN, and 32 MiB report.

## Multi-tag SIF progression

The next SIF1 command declared more payload words than fit in its first REF tag.
The scheduler now carries the remaining word count and destination across raw REF
continuation tags before accepting the following REFE transfer. A regression test
verifies two transfers in one chain and their exact cycle deadline.

The resulting IOP work armed a 16,352-word SIF0 packet whose IOP source tag ended
without an EE destination-chain end. SIF0 now models those two completion states
independently. The payload reaches EE address `0x00100000`, the IOP channel retires
and interrupts, and the EE channel remains armed until its own end condition.

At 30 million EE instructions the retail BIOS has left the old kernel-idle
boundary and entered CDVD initialization. At 100 million instructions both CPUs
remain instruction-valid: the BIOS has completed two `Restart Without Memory
Clear` passes, the EE is executing relocated user-memory code around `0x00258CB4`,
and the IOP has advanced to `0x0004E8BC`. No startup image is rendered yet; the
next evidence-driven boundary is the later CDVD/device handshake and first guest
GIF submission.

## SIO2 probe and relocated packed code

The next stable IOP boundary was a poll of SIO2 `RECV1` bit 12 at `0x0004E8BC`.
Focused tracing showed the guest configure four ports, submit two infrared probes,
write control `0xB1`, and request seven response bytes each time. The no-device
SIO2 model now exposes reset control `0x3BC`, disconnected command status
`0x1D100`, port status `0xF`, idle FIFO bytes `0xFF`, and IOP interrupt 17 when a
PIO transfer starts. Both probes complete and the IOP advances beyond the wait.

That progress reached optimized relocated EE code at `0x0026C6DC`. The trace
successively exposed PCPYH, PXOR, and PNOR; the surrounding guest routine also
uses PAND and wrapping PSUBB. All five operations now cover both 64-bit halves of
an R5900 GPR, preserve alias-safe source values, and have focused host tests.

The latest confirmed trace reaches `0x0026C6F8`, 20 bytes beyond the first packed
opcode boundary. The adjacent packed operations are implemented for the next
replay; this checkpoint does not yet claim visible BIOS graphics.
