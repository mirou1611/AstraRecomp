## Physical pixel provenance instead of visual guessing

Added an opt-in GS accepted-raster observer. Up to 16 aligned physical byte
addresses in Astra's **logical linear** 4-MiB GS memory can be watched. Each
event preserves the exact watched word before/after the operation, pre-blend
input, depth, quarter-grid coordinate, bound FRAME and GIF draw/register state.
Textured events also retain requested/addressed UV, format, wrapped texel address,
raw texel, TEXA-expanded color, vertex color and texture-function output. Sampling
metadata is captured before any aliased framebuffer write, not reread afterward.

The tracer keeps the latest 64 events per address, plus total/dropped counts and
the current raw word. Its generation is an **observed raster-operation ordinal**,
not a hardware memory generation. Draw sequence is per primitive kind; packet is
the frontend submission ordinal. EE cycle/next-PC describe the synchronous host
handoff, not historical GS bus cycles or an exact EE instruction causing a draw.

This is not a complete dynamic backward slice. Clear, IMAGE uploads and rejected
fragments are deliberately excluded. Fully masked and same-color accepted
operations are still reported. An empty list disables the observer; invalid
setup preserves an existing configuration. Callbacks must not mutate/re-enter GS.
No hardware swizzling, native-resolution coverage or display composition is
implied. The normal renderer remains the execution path; diagnostics are opt-in.

## Fractional sprite coverage and texture interpolation

The old rasterizer divided signed XYOFFSET-relative 12.4 coordinates by 64 before
deciding rectangle coverage, and discarded UV fractions before interpolation.
A right endpoint at native `639.9375` became quarter-grid 159; the exclusive loop
then skipped anchor 159/native 636. Positive fractional lower bounds incorrectly
included an anchor below the rectangle. Reversed/fractional texture rectangles
could sample the wrong texel, even when integer geometry looked correct.

Sprite bounds now retain signed fixed-point positions and ceil-round both edges
to select native anchors in the original half-open rectangle. Inclusive native
sprite SCISSOR lower bounds likewise round up to the first valid anchor. Upper bounds
remain inclusive. Raw UV0/UV1 and original signed geometry feed a single int64
affine rational expression; clipping and reversed bounds cannot restart/stretch
the texture. A descending UV near a texel boundary guards against truncating the
negative slope before adding UV0. Zero-area rectangles remain empty.

Primary reference basis is the pinned PCSX2 software rasterizer's fractional
rectangle bounds and original-origin affine prestep.
[PCSX2 v2.8.2 DrawSprite](https://github.com/PCSX2/pcsx2/blob/v2.8.2/pcsx2/GS/Renderers/SW/GSRasterizer.cpp#L1022-L1109).
The independent fixture tests native-anchor inequalities and long-double texture
expectations, not a copy of the implementation's ceil/rational helpers. This is
a correction to Astra's quarter-grid model, **not hardware-golden pixel accuracy**.
Triangle/line/point fractional coverage, native GS swizzling and filtering remain
separate limitations. One old REGLIST assertion was corrected: native [1,17)
covers anchors 4/8/12/16 (host 1..4), not host 0..3.

The pre-fix pixel observer also settles the black-band writer: sprite 183 in
submission 5379 at modeled EE cycle 298,392,589 changes `0x0A2D00` from
`7F6C2718` to `80000000`. FRAME is `A0050`, PRIM `46`, source `80FFFFFF`,
ALPHA `80000062`, i.e. subtract white from destination with FIX=128. The black
band is a real guest subtractive pass in this model, not uninitialized RAM.
Its stale right edge is a separate coverage defect; the fix must not remove the
intentional black pass simply to make the picture look better.

## Reproduction and capture controls

`ASTRA_GS_WATCH` accepts a strict comma-separated hexadecimal address list:

```sh
ASTRA_GS_WATCH=110a60,101b20,110bb0,110ba0,9e1f0,a31e0,a2d00
```

`ASTRA_GS_FRAME_STEPS` accepts up to 16 positive, strictly increasing decimal
instruction counts no greater than MAX_STEPS; FRAMEBUFFER_PPM must be provided.
Snapshots occur after the requested completed instruction and graphics service.
The files are `<FRAMEBUFFER_PPM>.step-N.ppm`, with FRAME/PMODE/DISPFB labels.
Exactly one supported display circuit additionally produces
`<FRAMEBUFFER_PPM>.step-N.ppm.linear-display.ppm`, respecting DBX/DBY. Unsupported
display configurations explicitly skip this secondary file. It remains a raw
linear display-buffer probe, **not hardware scanout**. Early stops report actual
versus requested captures. Signs, whitespace, partial parses, duplicate watches,
unaligned/out-of-range addresses, list overflow and numeric overflow are rejected.

The local before/after experiment uses the same BIOS and command parameters:

```sh
ASTRA_TRACE_SECONDS=600 \
ASTRA_GS_WATCH=110a60,101b20,110bb0,110ba0,9e1f0,a31e0,a2d00 \
ASTRA_GS_FRAME_STEPS=280000000,285000000,290000000,295000000,300000000 \
build-release/ps2bios_trace ps2-0200e-20040614-100914.bin \
  0 300000000 1 0 8 0 0 0 - build-release/pixel-watch-fixed-300m.ppm \
  - build-release/pixel-watch-fixed-display-300m.ppm
```

The tracer exits 1 for reaching MAX_STEPS while still running; this is expected,
not a crash. Before-fix executable/log/captures use the `pixel-watch-before`
prefix; post-fix artifacts use `pixel-watch-fixed`. None are source-controlled.
