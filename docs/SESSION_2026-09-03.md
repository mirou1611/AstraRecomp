## First guest GIF DMA and sprite frontend

## Outcome

The retail BIOS crossed the former CDVD/SIF boundary and issued its first two
normal-mode GIF DMAs. AstraRecomp now retires those transfers, queues exact
payload snapshots, decodes packed A+D GIFtags in a separate frontend, and
rasterizes the observed GS sprite through the existing quarter-scale backend.

The first captured transfer starts at EE step `245675519`, PC `0x0026EF08`,
with `MADR=0x001F0A60` and `QWC=15`. Its first qword is a packed A+D GIFtag
with `NLOOP=14`, `EOP=1`, and `NREG=1`. The register stream sets FRAME/ZBUF,
XYOFFSET, SCISSOR and draw state, then emits a PRIM=SPRITE from `(0,0)` to
`(640,256)` after applying XYOFFSET. At quarter scale this covers `(0,0)` to
`(160,64)`.

With GIF DMA retirement enabled, a 300-million-step replay no longer waits on
channel 2. It reaches step `245778750`, observes two GIF DMA starts, submits two
packets, emits two sprites, and then stops on a concrete VU0 macro instruction:

```
PC 0x002736E4: 0x4A202128  VADD.W vf4, vf4, vf0
```

Implementing the masked VADD advances to the next instruction:

```
PC 0x002736E8: 0x4BE5233D  VMR32.XYZW vf5, vf4
```

VMR32 is now implemented as an alias-safe `Y,Z,W,X` lane rotation. The
following static instructions repeat it for `vf6` and `vf7`, forming a small,
coherent BIOS matrix-construction helper.

## Architecture decisions

- `Memory` models normal-mode channel-2 transport, deadlines, register
  retirement, and the DMAC status bit. It does not interpret GIFtags.
- `Gif` is a new packet/register frontend layered over `Gs`. This follows the
  useful frontend/backend separation seen in PS2Recomp without replacing
  AstraRecomp's interpreted EE/IOP correctness oracle.
- Completed DMA data is snapshotted into an ordered queue so the producer may
  continue independently of frontend servicing.
- Packed-mode NLOOP accounting consumes exactly `NLOOP * NREG` qwords. EOP does
  not prematurely discard later GIFtags within the same DMA payload.
- The exact captured BIOS packet and both newly encountered VU0 instructions
  are regression-tested rather than approximated as no-ops.

## VIF1 transport and VU1 setup frontier

VIF1 source-chain DMA is now modeled with timed completion, TTE tag-data
insertion, channel-register retirement, DMAC channel-1 interrupt status, and an
ordered payload queue. The chain walker handles REFE, CNT, NEXT, REF/REFS,
CALL/RET (two-deep stack), and END tags. As with GIF, transport stays in
`Memory`; the new `Vif1` frontend owns command parsing and VU-visible writes.

The first real BIOS chain starts at EE step `248772997`, PC `0x0021D6B4`, with
`CHCR=0x145` and `TADR=0x00273990`. It completes and retires correctly. Its TTE
stream begins with NOP plus `MPG NUM=0xE5, ADDR=0`, loading exactly 229 VU1
microinstructions. PCSX2's current `Vif_Codes.cpp` confirms that a nonzero MPG
NUM is used directly and zero denotes 256; the two following words are real
VIF commands rather than an off-by-one microinstruction.

The frontend now handles NOP, STCYCL, the payload-free setup/synchronization
commands encountered so far, STMASK, STROW/STCOL, MPG, and the captured
contiguous `V4-32 UNPACK`. That UNPACK writes 22 four-lane vectors into VU1
data memory. Parsing then reaches command `0x14000000` (`MSCAL`): the BIOS is
requesting execution of the microprogram it just uploaded.

Two scalar COP1 instructions on the setup path were also implemented from
their exact captured encodings: ordered `C.OLT.S` (`0x46050034`) and ordered
`C.OLE.S` (`0x46032036`). With those additions, the replay no longer stops on
an invalid EE instruction and reaches the full 249,000,000-step ceiling at PC
`0x0026559C` (222,681 steps beyond the former C.OLE boundary).

The framebuffer remains `0/17920` nonzero pixels with hash
`AE6BFFA9F3064B83`. This is expected and is not reported as an intro boot:
`MSCAL` exposes the next concrete requirement, VU1 microprogram execution and
its path-1 GIF output. Image-mode GIF transfer/VRAM support is the other known
graphics requirement.

Host validation passes both test targets, including exact VIF1 chain ordering,

passes; `build-vita/ps2vita.vpk` has SHA-256

## First VU1 program and path-1 GIF tags

A separate functional `Vu1` interpreter now consumes the uploaded micro memory
instead of aliasing EE/VU0 macro state. `MSCAL` starts at its encoded address;
`MSCNT` resumes at the retained TPC. The initial captured program currently
uses and regression-tests paired upper/lower execution, I immediates, the E-bit
delay pair, IADDIU, IADD, BAL/JR with branch delay, masked LQI/SQI, and the
MULAx/MADDAy/MADDAz/MADDw matrix dot-product sequence.

The real BIOS `MSCAL 0` now executes 55 microinstruction pairs, calls its setup
routine at `0x648`, transforms VU data, returns, and reaches `XGKICK` at `0xC0`.
It then executes the E delay pair and stops cleanly at TPC `0xD8` with no
unsupported VU opcode.

`XGKICK` addresses VU1 qwords through `VI[is]`, computes each path-1 transfer
from its GIFtag format, and queues tags independently until EOP or malformed
data. This matches PCSX2's current tag-at-a-time path-1 transfer model and
preserves valid tags before a later rejected tag. The captured kick begins at
VU byte address `0x120` with tag `0x1000000000000002` (packed A+D, NLOOP=2).
It queues two valid tags and then rejects one incomplete later tag.

The 248.8-million-step replay therefore raises GIF packets from 28 to 30 and
parsed packed tags from 278 to 280. VIF has unpacked 39 vectors and its next
command is `MSCNT` (`0x17000000`). The framebuffer is still `0/17920` nonzero
pixels with hash `AE6BFFA9F3064B83`; the first path-1 data is setup-only and is
not represented as a visible intro milestone. MSCNT resume behavior is already
implemented and unit-tested; replaying the continuation is the next slice.

SHA-256 is
