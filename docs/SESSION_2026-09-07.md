after STCYCL `01000404`. It uploads 22 vectors to TOPS-relative qword zero,
then MSCAL `14000000` occurs at 0x08A0. The source payload already contains:

| VU qword | Four source words |

## Coworker2 review (after checkpoint a7aa422)

Read the entire user-provided `coworker2` file (no extension). Its strongest
near-term suggestions are temporal PATH1 consumption, delayed-result VU
scoreboards, causal provenance, packet invariants, and deterministic replay.
These are research directions, not evidence that the current intro blocker is
solved. The next concrete EE stop remains opcode 4BC522FE at 002738F8;
the later rejected VIF submissions also need independent investigation.

Apply the small-reproducer recommendation immediately to subsequent opcode
work, continuing the captured normalization and transpose fixtures. Extend
existing DMA-span/store diagnostics toward first-rejected-packet provenance
before committing to a full shadow-memory implementation. Debug metadata must
be opt-in and bounded; desktop memory and tracing overhead are not irrelevant.

Temporal XGKICK needs a synthetic producer/consumer regression and explicit
transfer scheduling/backpressure semantics before changing the BIOS path.
Do not introduce a BIOS-specific delay or fabricate EOP. A short captured
payload is not necessarily architecturally impossible when more data may
arrive later. Likewise, a scoreboard requires verified latency, hazard, and
flag rules rather than exposing all pending values immediately.

Whole-machine snapshots are valuable but require complete device and event
state plus restore-equivalence tests; CPU/RAM-only snapshots are insufficient.
Packet minimization must preserve command boundaries and the same failure
signature, not merely produce any parser rejection.

Defer entropy-guided traces, narrow-value specialization, lane slicing, packet
AOT, and cross-domain specialization until correctness fixtures exist. Their
guards must cover overflow, observable flags, events, and aliasing, with a
working fallback. A longest-path profiler predicts frame time only when actual
scheduling/resource constraints are represented. No Vita speedup is established
by this proposal; physical-device measurements remain required.
