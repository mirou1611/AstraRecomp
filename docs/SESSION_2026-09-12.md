Local capture `build-release/vif-origin-first.txt/.ppm` reports 496 upload
records and seven VU runs, with no dropped records:

- Initial MSCAL at stream offset 08A0 executes pairs [0,55), PC 0000 to 00D8,
  and increases PATH1 rejection count from zero to one.
- The following MSCNT at 09C8 starts at pair 55 / PC 00D8. The previously
  identified header write at pair 75 is therefore in a later VU invocation.
- Before any VU execution, stream bytes 0860..086F upload the tag at VU data
  0120: words 00000002, 10000000, 0000000E, 00000000.
- Stream bytes 0870..089F upload zeros to 0130..015F, including the next header
  slot at 0150. The initial upload ends before address 0160.
- VU store pair 17 / PC 06A8 writes float bits 420F028B at 0160; these are later
  interpreted as a GIF tag after the unterminated zero header.
- Inspection of the captured command stream finds no STMOD, STMASK, STROW or
  STCOL preceding this failure, so ignored versions of those commands do not
  explain this particular capture.

Thus a later header write is not evidence that the first kick should wait for
it. The next investigation should trace EE-side construction of the initial
header/GS-register payload, including the previously watched 00274200 region
and upstream source values. This does not establish the ultimate root cause or
exclude other timing defects; it narrows this specific hypothesis.
